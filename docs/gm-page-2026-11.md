# GM 玩家页（后台）· 数据表现格式整理（2026-11 快照）

> 来源：用户 2026-11 粘的一整页 GM 玩家查询页（`staff-tio-cn.fantanggame.com/index.php/player`，页面标题 `Summer`）。
> 这份文档只记「**数据的表现格式**」这一层：哪块多了列 / 换了写法 / 加了新区块，工作台要不要跟着改。
> 工作台里真正吃这些格式的地方：`public/index.html` 的 `parseOrderLog`（订单记录）、`SD_*`（七日任务进度日志）、`DEFAULT_*_MAP`（映射表，见 AGENTS.md「游戏数据管线」）。

## 1. 已经跟着改了的（本轮代码）

| 后台区块 | 表现格式的变化 | 工作台处理 |
|---|---|---|
| 任务进度 → **七日任务进度日志** | 「任务ID」和「老进度」之间**多了一列 `任务需求`**（例：`收集27000个铜钱`），一行变成 **9 列**；老日志还是 8 列 | `SD_LOG_ALIASES` 加 `任务需求 → demand`；`SD_LOG_ORDER` 变 9 列，并加 `SD_LOG_ORDER_LEGACY`（8 列）+ `sdLogOrderFor(cells)` **按第 5 格内容自动挑列序**（数字/「-」= 老版） |
| 同上 | 用户口径：**任务需求数量以复制的日志文本为准** | `sdParseDemand()` 从「任务需求」里取数（支持 `2.7万` 写法）；话术的**任务名与目标都取日志**，表里的目标只作兜底；`± 一期` 估出来的那一行若跟日志需求对不上，**天数 / 奖励也不借它的**（否则会把「还差多少」算到别的任务头上） |
| 同上 | 排期下拉**新增 38 / 39**（37 之后） | `SD_SCHEDULE` 补 `38\|2026/11/16 8:00~2026/11/25 7:59`、`39\|2026/11/23 8:00~2026/12/2 7:59` → 抬头能写时间窗了 |
| 棋盘 → **订单记录** | 制表符「扁平化」：列不再对齐，`难度分` / 奖励组 id 会**跟奖励挤在同一行前面**（`22⇥玲珑糕点 x 3`）；`订单需求` 一格多行棋子（续行单独成行）；一行里可能挤**多条** `名字 x 数量` | `parseOrderLog` 本来就是「按行分块 + 按内容认」，难度分/纯数字细胞已剔除；本轮再补：**一行里连续多条 `名字 x 数量` 全部收下**，收完剩下的尾巴仍当来源说明丢掉 |

## 2. 格式变了但工作台**不用**跟的（没有消费点）

- **订单类型下拉** 现在是 100–114：`100 固定订单 / 101-104 随机订单 / 105 特殊订单 / 106 随机订单 / 107 好感度订单 / 108 回归订单 / 109 随机订单 / 110 回收订单 / 111 龙宫夺宝订单 / 112 pk100订单 / 113 鹦鹉订单 / 114 猫咪叠罗汉订单`。订单日志的话术里**不标订单名**（用户 2026-11「算了，不标这个了」），只用来认「过期」，所以没有映射表要维护。
- **日志来源下拉** 7 种：`1 创建 / 2 完成 / 3 过期 / 4 插槽变更 / 5 奖励变更 / 6 需求变更 / 7 异常数据-删除`。工作台只认「完成 / 删除 / 创建 / 过期」这四个词（另外三个是后台改单动作，不出话术）。
- **棋盘操作记录** 的 `opFrom` 已到 **269**（`道具使用-锦鲤`），页面本身就缺 52；`DEFAULT_SOURCE_ID_MAP` 268 条与之逐条一致（见 AGENTS.md 第三～五轮核对）。
- **活动下拉** 41 个类型（含 `87 糖葫芦2v2` / `84 新拼图活动` / `75 95打怪棋盘` / `73 93走地图棋盘` / `81 体力排行榜` / `60 限时累充` / `59 大转盘` / `70 还愿锦鲤`），`DEFAULT_ACTIVITY_TYPE_MAP` 41 条一致。
- **任务进度** 现有 6 个板块：`七日任务 / 七日任务进度日志 / 家具每日任务 / 抖音极速金(累计) / 抖音极速金(每日) / 茶楼经营簿 + 茶楼经营簿日志`。除七日任务外工作台都没有做话术。
- **新增/存在的其它区块**：好感度 + 好感度经验日志、自宅背包 / 自宅方案 / 换装道具 / 换装方案、排行榜查询（限时排行榜 / 厨王争霸 / 春生雅艺会，带近期排期 `rankScheduleData`）、订阅推送、广告日志 / 广告展示、兑换码记录、邀请记录、签到记录、镜像（ajax 空壳，JSON 要另抓）。工作台暂时都不消费。
- **货币 / 道具分类**：`100 货币` 下 `101 体力 / 102 铜钱 / 103 红宝石 / 104 pass卡经验值 / 105 好评点 / 106 抖音音符 / 107 装修券`；另有 `900 活动道具 / 901000 锦鲤道具 / 4100000 换装部件 / 4209000 换装分享 / 840 特殊补偿 / 2000000 随机奖励道具`。物品名表抽检 `101/102/103/9001–9004` 全部一致（`102 铜钱`、`103 红宝石`、`9003 乌鹭棋盒`）。
- **卡包名** 151–179 与 `PACK_NAME_MAP` 一致；173–179（霞光 / 幻狐）仍按工作台的手写词序（见 AGENTS.md「已定语义 3」的已知例外）。
- **玩家基础信息表**：新增/保留了 `是否回归玩家`、`月充值积分`、`解锁订单类型 orderType`、`特殊订单 specialOrders`、`当前特殊订单ID`、`汇总好评点数据 goodReview`、`pass卡数据 / 棋盘pass卡数据 / 上期棋盘pass卡数据`、`订阅数据`、`建筑皮肤`、`解锁棋子图鉴`。其中 **`goodReview` 现在是带 `orderRefresh[{smile,orderNum,orderType}]` / `superStartTime` / `superExpireTime` / `superTriggerNum` / `totalScoreSuper` / `finishedNormalCount` 的一整份 JSON**（超级好评点的窗口与触发次数都在里面），工作台目前只用「好评点奖励记录」那块，不用这份。
